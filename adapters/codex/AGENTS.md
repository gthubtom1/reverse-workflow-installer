# Codex reverse workflow

For reverse-engineering, security-analysis, protocol, frontend-signature, reconstruction, behavior-comparison, version-tracking, or knowledge-maintenance tasks, read the global Codex `reverse-workflow` Skill before using ordinary tools.

Read the installed receipt at `{{RECEIPT}}`, then follow its `reverse.root`, original `RULES.md`, native router, PRIMARY and scope/case contracts. The global Codex Skill at `{{CODEX_SKILL_ENTRY}}` is the task entry. REA is an analysis backend selected by the reverse router, and Spec Kit is used only when an explicitly selected independent project needs its own specification and task contract.

Do not install or invoke Pi-only profiles, shell-guard, Craft-Pi, Pi package registrations, Impeccable Pi resources, or the optional Pi local packages in Codex. The default implementation path uses the original Spec runner and a bounded Worker, which returns a candidate for the original chain to accept. Upstream Craft Anything's Codex setup is optional host integration and does not establish R46 bounded-backend qualification: standalone `rebuild_start` returns `consent_required`; app consent or an explicit user choice of `--allow-run` is separate. Never add that flag silently. Use a Craft execution backend only after the original runner explicitly selects an actually qualified batch, and return its candidate to that runner.
